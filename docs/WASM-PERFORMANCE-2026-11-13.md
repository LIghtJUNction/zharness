# zharness Wasm 适配层性能记录 — 2026-11-13

本次测试比较同一个实际 Wasm 插件经过 zplugin 直接调用、zharness 命名适配、
Executor 和 Router 的成本。3 个独立进程各执行 24 项、每项 31 批，共保留
2,232 条原始记录。所有预热后成功调用均测得 0 次分配、0 字节净存活增长；
这个结论不包含初始化、任意插件业务或错误格式化路径。

64 B 命名字节调用的代表值为 180.627 ns，匹配的 zplugin 字节基线为
162.338 ns；1 MiB 分别为 78.918 μs 和 78.695 μs。代表值是三个进程各自
批均值 p50 的中位数，**不是单次请求的 p50/p99，也不是完整 agent 延迟**。

## 环境与方法

| 项目 | 本次测量 |
| --- | --- |
| CPU | AMD EPYC 9V74 80-Core Processor；共享容器，不是独占裸机 |
| 系统 | Linux 6.18.57，x86-64，glibc 2.41 |
| CPU 亲和性 | 继承允许集合中的 CPU 0；不能排除同机其他负载 |
| Rust / Cargo | 1.100.0；Rust 提交 `0ef1bc386059596dada8fb65b50425aab2ea637a` |
| LLVM | 23.1.5 |
| 宿主构建 | opt-level=3、thin LTO、codegen-units=1、panic=unwind |
| Guest 构建 | wasm32-unknown-unknown、opt-level=3、LTO、panic=abort、64 KiB 线性栈 |
| 依赖 | zplugin 0.3.0 / Wasmi 2.0.0；完整锁文件包含在源码提交中 |
| Guest | 1,077 B；SHA-256 `ea2ac81a67311dc98ab83733419a13ffaecac600b8121313d915233daece4aa2` |
| 覆盖规模 | 3 个新进程 × 24 项 × 31 批；一个操作映射、一个路由 |

各路径使用同一个 guest、默认资源限制、相同所有权、单线程串行调用、输入/输出
复制和输出清零语义。guest 真实执行 echo；宿主使用 `black_box` 消费结果，
计时前后断言结果等于输入，避免将测量工作优化掉。

输入为 0 B 原始字节，或 2 B 的 `{}`、64 B、4 KiB、1 MiB 的 JSON 对象。
0 B 不能构成此处的合法工具 JSON，因此只用于字节路径，不强行混入 Executor 对照。

| 路径 | 计时范围 |
| --- | --- |
| `direct_bytes` | zplugin 的完整沙箱字节调用，包括运行预算、guest 执行和跨边界复制 |
| `extension_bytes` | 上述工作，加 zharness 操作名映射和错误适配 |
| `direct_text` | 字节基线，加与 Executor 相同的输出 UTF-8 校验 |
| `executor` | 命名适配器通过 Executor 调用，含 UTF-8 校验 |
| `router` | 公共名称查找、启用状态检查、Executor 分发及上述完整执行 |
| `*_load_drop` | 从现有模块字节验证、初始化、绑定、销毁；不包括文件 I/O 和编译 guest |

稳态计时排除模块加载、JSON 参数解析、路由构造以及调用者缓冲分配。字节适配器
只与字节基线比较，Executor/Router 只与含 UTF-8 校验的文本基线比较。
这里没有把更便宜的字节路径当作完整文本调用的对照。

每项先预热最多 64 次，再测 31 批。0/2/64 B 每批 10,000 次，4 KiB 每批
1,000 次，1 MiB 每批 16 次，加载/销毁每批 10 次。每批只在循环两端计时，
除以调用次数得到 ns/op。CSV 保留每批耗时、迭代数、分配次数和净存活字节。
脚本的 p50/p95/p99 采用排序后 `floor(p × (n−1))` 索引，表示**批均值分布**。

## 实测结果

下表单位为 ns/op，均为三个进程 p50 批均值的中位数。

| 输入大小 | zplugin 字节基线 | WasmExtension 字节 | zplugin 文本基线 | Executor | Router |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0 B | 141.357 | 156.923 | — | — | — |
| 2 B | 165.166 | 173.707 | 162.204 | 179.310 | 170.498 |
| 64 B | 162.338 | 180.627 | 174.665 | 187.174 | 177.907 |
| 4 KiB | 360.814 | 335.596 | 435.086 | 407.864 | 420.584 |
| 1 MiB | 78,695 | 78,918 | 98,945 | 98,604 | 99,033 |

1 MiB 行在表内四舍五入到整数纳秒；完整精度见 CSV。64 B 字节适配路径的
代表值差为 +18.289 ns，Executor 对应文本基线为 +12.509 ns。这是本次构建的
观察值，不是对所有机器、路由数量和插件的固定开销保证。

| 路径 | 代表值 | 三进程 p50 最小—最大 |
| --- | ---: | ---: |
| 字节适配，0 B | 156.923 ns | 153.382—215.455 ns |
| 字节适配，64 B | 180.627 ns | 175.531—192.563 ns |
| 字节适配，4 KiB | 335.596 ns | 331.450—335.706 ns |
| 字节适配，1 MiB | 78.918 μs | 78.901—80.524 μs |
| zplugin 加载/销毁 | 45.210 μs | 45.132—45.775 μs |
| WasmExtension 加载/销毁 | 44.910 μs | 43.908—45.206 μs |

若干包装路径出现比基线更小的数值，尤其是 4 KiB。这不能证明包装会加速引擎；
测试按固定顺序运行，共享机器调度、缓存和代码布局会影响结果。当前数据足以说明
此样例没有引入每次调用的强制堆分配，不能推出普遍加速比、亚微秒业务延迟或请求尾延迟。

## 分配和内存

分配器统计 Rust `System` 的 `alloc`、`alloc_zeroed`、成功 `realloc` 及其请求
Layout 大小。它覆盖本宿主中链接的解释器，但不代表任意原生动态库的独立分配器。

| 指标 | zplugin 直接路径 | zharness 适配路径 |
| --- | ---: | ---: |
| 每次预热后成功调用分配次数 | 0 | 0 |
| 每批预热后调用净存活增长 | 0 B | 0 B |
| 每次完整加载/销毁分配次数 | 122 | 122 |
| 每次加载/销毁累计请求字节 | 2,257,002 B | 2,257,002 B |
| 加载/销毁期间峰值额外存活请求字节 | 2,248,564 B | 2,248,564 B |
| 初始化后保留的请求堆字节 | 2,247,806 B | 2,247,806 B |
| Guest 线性内存 | 2,228,224 B | 2,228,224 B |

全部 2,232 批均断言净存活增长为 0；全部稳态批同时断言分配次数为 0。
线性内存包含样例的两个 1 MiB 固定缓冲和 guest 栈/布局开销，因此并非空插件
的最小内存占用。内存数字不包含分配器元数据、OS/RSS 或 realloc 内部临时内存，
也不将默认 16 MiB guest 上限冒充进程总内存上限。

## 能力边界与待测项目

已实现并验证的是同步、无 imports 的 zplugin Wasm32 协议与命名工具适配。
本报告没有测量多路由规模、真实业务、授权 hooks、JSON 解析、文件 I/O、跨进程
隔离、WASI、异步任务或端到端 agent 工作流。原生插件历史结果见
[2026-11-12 记录](PLUGINS-PERFORMANCE-2026-11-12.md)；其版本和方法不同，不能
拿来直接计算此次 Wasm 的性能比值。

进一步的性能计划是固定机器上的随机顺序/成对测量、多路由规模和实际业务负载。
这些没有纳入本次已完成结果。Wasm 的安全边界与资源限制以
[PLUGINS.md](../PLUGINS.md) 和 [SECURITY.md](../SECURITY.md) 为准；性能测试不是
沙箱不可逃逸的证明。

## 表述自检

1. 问题明确：测量 zharness 在已有沙箱之上增加的适配成本，而非宣称新的执行引擎。
2. 证据充分：公开不可变源码提交、完整原始批记录、环境、编译参数和分配断言。
3. 对照公平：所有权、线程、生命周期、guest 和复制一致，文本路径包含相同 UTF-8 校验。
4. 推论克制：不把批均值分位数写成请求尾延迟，不把计数器堆字节写成 RSS。
5. 可复现且有边界：列明样例、规模、测量噪声、未测能力和后续实验；不以计划代替结果。
